# Диагностика качества данных Wialon / GPS / ДУТ / CAN

Главная цель интеграции Wialon — не просто показывать GPS-данные, а выявлять технику, по которой данные считаются неправильно: моточасы, пробег, расход топлива, ДУТ/CAN, координаты и связь.

## Куда вывести на сайте

Раздел: `GPS/ТБ → Диагностика данных`.

Дополнительно краткие индикаторы должны отображаться в:

- `Главная` — общий статус проблем по GPS/данным;
- `Техника → Карточка техники` — диагностика конкретной единицы;
- `Горная → Суточный отчет` — сравнение часов по сводке и Wialon;
- `Топливо` — сверка расхода, заправок, сливов и остатков.

## Основная таблица

Колонки:

| Колонка | Смысл |
|---|---|
| Техника | гаражный номер / наименование техники сайта |
| Участок | текущий участок / проект |
| Wialon | Wialon ID и объект |
| Последний сигнал | время последнего сообщения |
| GPS | онлайн / нет связи / нет координат |
| Моточасы | норма / ошибка / нет данных |
| Пробег | норма / ошибка / нет данных |
| Топливо | норма / ошибка / нет данных |
| ДУТ | норма / нет датчика / скачки / нет данных |
| CAN | есть / нет / ошибка |
| Сводка | расхождение с часами по участку |
| Статус | Норма / Предупреждение / Ошибка / Нет данных / Требует проверки |
| Проблема | текстовое описание отклонения |
| Рекомендация | что проверить |

## Статусы

- `Норма` — критичных отклонений нет.
- `Предупреждение` — есть подозрение, нужна проверка.
- `Ошибка` — данные явно некорректны.
- `Нет данных` — Wialon/датчик не передает нужный показатель.
- `Требует проверки` — система не может однозначно определить причину.

## Проверки моточасов

Система должна выявлять:

- техника двигалась, но моточасы не растут;
- двигатель работал, но моточасы равны 0;
- моточасы резко прыгнули;
- моточасы больше нормы смены;
- моточасы сильно отличаются от часов по суточной сводке;
- нет данных по моточасам за смену;
- разные значения между Wialon, CAN и датчиком зажигания.

Пример сообщения:

`DT59: по GPS движение было 7,2 часа, а моточасы 0,4. Возможна ошибка датчика моточасов.`

## Проверки пробега

Система должна выявлять:

- координаты менялись, а пробег 0;
- пробег слишком большой для смены/участка;
- пробег резко прыгнул;
- пробег по GPS сильно отличается от CAN/одометра;
- техника стояла, но пробег начислился;
- нет координат, но есть пробег.

Пример сообщения:

`P128: пробег за смену 286 км, при этом техника находилась на участке. Требуется проверка GPS/одометра.`

## Проверки топлива

Система должна выявлять:

- расход есть, но техника не работала;
- техника работала, но расход 0;
- расход на моточас выше нормы;
- расход на 100 км выше нормы;
- резкое падение топлива без движения;
- заправка не совпадает с ведомостью;
- остаток топлива скачет;
- ДУТ показывает нереальные значения;
- отрицательный расход;
- расход больше емкости бака.

Пример сообщения:

`DT59: расход 180 л за смену, моточасы 2,1. Расход 85,7 л/мч — выше нормы. Проверить ДУТ/слив/заправку.`

## Проверки датчиков и связи

Система должна выявлять:

- нет сигнала GPS;
- нет координат;
- нет ДУТ;
- нет CAN;
- нет зажигания;
- нет моточасов;
- нет скорости;
- данные не обновлялись больше 30 минут / 2 часов / суток;
- объект есть в Wialon, но не сопоставлен с техникой сайта;
- техника есть на сайте, но нет объекта Wialon.

## Сравнение источников

Для диагностики система должна сравнивать:

1. Суточную сводку участка.
2. Wialon GPS.
3. Моточасы Wialon.
4. Пробег Wialon.
5. Топливо / ДУТ.
6. CAN, если подключен.
7. Нормы расхода.
8. Распорядок смены участка.

## Первый этап реализации

В первую очередь реализовать базовую диагностику связки Wialon:

- объект Wialon сопоставлен / не сопоставлен;
- техника сайта имеет / не имеет Wialon-объект;
- объект Wialon скрыт / активен;
- UID терминала есть / отсутствует;
- SIM указана / отсутствует;
- дата последней загрузки Wialon актуальна / устарела;
- отдельные счетчики ошибок и предупреждений.

## Второй этап реализации

После подключения отчетов/датчиков Wialon добавить расчеты:

- моточасы за смену/сутки;
- пробег за смену/сутки;
- расход топлива за смену/сутки;
- остаток топлива;
- заправки;
- сливы;
- сравнение с нормами;
- сравнение с суточной сводкой.

## Формулировка для ТЗ

В системе необходимо реализовать блок диагностики корректности данных Wialon/GPS.

Блок должен автоматически выявлять некорректный расчет моточасов, пробега, расхода топлива, показаний ДУТ/CAN и статуса GPS. Система должна сравнивать данные Wialon с суточной сводкой, нормами расхода, распорядком смены участка, пробегом, движением техники и данными датчиков.

При выявлении расхождений система должна присваивать технике статус: `Норма`, `Предупреждение`, `Ошибка`, `Нет данных`, `Требует проверки`, а также отображать причину отклонения и рекомендацию по проверке.
